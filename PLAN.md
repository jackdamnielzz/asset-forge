# Asset Forge — Plan

> Working name. Our own asset-creation tool, in the spirit of Blender, built so that
> **AI models can drive it completely** — and humans can too.

## Goals (in order of importance)

1. **Beautiful assets.** The output must look good enough to ship in a real game.
2. **Fully AI-controllable.** Everything a human can do in the window, an AI can do
   through an API. Claude Code first, but any AI model or script must be able to use it.
3. **Expandable.** Start small, but built so new tools can be added like Lego bricks
   without rewriting the core.
4. **Ours.** Runs locally on our own machines, no subscription, no lock-in.

## Core idea: one engine, many ways to control it

```
   You (mouse)     Claude Code     Other AIs / scripts     Command line
        │               │                   │                    │
        ▼               ▼                   ▼                    ▼
   ┌─────────┐    ┌──────────┐       ┌────────────┐        ┌─────────┐
   │ Window  │    │   MCP    │       │  HTTP API  │        │   CLI   │
   │  (UI)   │    │  server  │       │   (REST)   │        │         │
   └────┬────┘    └────┬─────┘       └─────┬──────┘        └────┬────┘
        └──────────────┴─────── same commands ──────────────────┘
                                   │
                          ┌────────▼────────┐
                          │   CORE ENGINE   │  scene, shapes, materials,
                          │                 │  generators, render, export
                          └────────┬────────┘
                                   │
                    ┌──────────────┼──────────────┐
                    ▼              ▼              ▼
               Plugins        Recipe files     Exports
             (new tools)     (scene as text)  (GLB, PNG, sprite sheets)
```

- **Command-first design:** every action (add shape, set material, bevel, render,
  export) is a named command with clear inputs. The window's buttons call the same
  commands. Nothing exists only in the UI.
- **MCP server:** the standard "plug" that Claude Code, Claude Desktop, Cursor and
  other AI tools understand. Primary AI interface.
- **HTTP API:** for any other program or AI (OpenAI, Gemini, local models, Python scripts).
- **CLI:** run commands or whole recipes from a terminal; good for batch jobs.
- **Recipe files:** a whole asset described as readable text (JSON). An AI can write
  one, the engine builds it, and the same recipe always gives the same result.
- **Live view:** when an AI changes something, you see it happen in the window.
- **AI "eyes":** a `render_preview` command returns an image so the AI can *look* at
  its work, judge it and improve it. This make → look → fix loop is key to quality.

## How we get beautiful results

| Ingredient | What it means in plain words |
|---|---|
| Realistic materials (PBR) | Metal shines, wood is matte, rust is rough; materials react to light like real ones |
| Lighting presets | Studio, outdoor, moody night — one click (or one command) for good light |
| Bevels & smoothing | Slightly rounded edges; the #1 trick that makes 3D look real instead of "computer-made" |
| Procedural textures | Wood grain, rust, stone, scratches generated by code — endless variations |
| Generators | "Make a crate / rock / barrel / tree" with sliders (size, wear, style) |
| Style presets | Realistic, stylized/hand-painted, low-poly, toon, **pixel-art render** |
| 3D → 2D sprites | Render a 3D model from 4/8 directions into pixel-art sprite sheets for 2D games |
| Image import | Your own pictures as textures, decals or reference |
| Quality checks | Automatic checks (scale, polygon count, missing textures) before export |

## Technology (simple version)

- **Language:** modern JavaScript (web-style code; runs everywhere, huge ecosystem, no build step).
  We can move to TypeScript later if the codebase grows large.
- **3D engine:** three.js (free, mature, renders in real time).
- **Geometry helpers:** libraries for bevels, boolean cuts (manifold-3d), etc.
- **Exports:** GLB/glTF (opens in Godot, Unity, Unreal, Blender), PNG, sprite sheets.
- **Desktop app:** later wrapped as a real Windows program (Tauri or Electron).
- **Optional later:** plugins that call AI image generators for textures, or Blender
  in the background for very heavy rendering.

## Roadmap

### Phase 1 — Foundation ✅ done (2026-10-23)
- Core engine with a command system and scene recipe format
- Window with 3D view: orbit camera, select, move/rotate/scale
- Basic shapes: cube, sphere, cylinder, plane; image import as texture
- Basic materials (colour, metal, rough) and 2–3 lighting presets
- **MCP server + HTTP API from day one**, including `render_preview`
- Save/open project, export GLB and PNG

### Phase 2 — Beauty ✅ done (2026-10-23)
- Soft corner shadows (ambient occlusion) and real glow (bloom)
- Style switch: realistic, toon (with outlines), low-poly, clay
- Generated materials: wood, planks, brushed/scratched metal, rust, stone, brick, tiles, fabric, concrete, hand-painted
- "Age" slider: worn edges, grime, scratches, faded colour

### Phase 3 — Shapes & generators
- Repeat (row / circle) and mirror
- 3D text
- Spin tool (lathe): vases, bottles, chess pieces, columns
- Picture → 3D (extrude a silhouette or logo)
- Cut and combine shapes (booleans)
- Generator library: barrel, chest, rock, tree, crystal, potion bottle, sword, lamp post, fence, coin

### Phase 4 — Made for our games
- Icon maker (consistent inventory icons, in batches)
- 3D → pixel-art sprites from 4/8 directions, sprite sheets
- Godot export (straight into a project, with collision shapes)
- Simple animations (spin, bob, open lid) → animated sprite sheets / animated GLB
- Level building kits (snapping wall/floor/corner pieces)

### Phase 5 — AI superpowers
- Recipes: every asset remembers how it was made and can be re-made with changes
- Variations grid ("make 12 versions")
- Quality check (floating parts, overlaps, size, polygon count)
- House style (shared palette, materials and lighting for one game)
- AI texture generation (e.g. PixelLab) and photo → seamless texture

### Phase 6 — Comfort & sharing
- Size reference (1.8 m person)
- Asset library with thumbnails, tags and search
- Real Windows program with its own icon
- Online access with a password for friends and remote AIs

## Example: what using it with Claude Code looks like

> "Make a rusty sci-fi supply crate in three variants and export them for Godot."

Claude would call: `create_from_generator(crate)` → `set_material(rusty_metal)` →
`bevel(0.02)` → `set_lighting(studio)` → `render_preview` (looks at it, adjusts) →
`export(glb)` ×3. You watch it happen live in the window.
